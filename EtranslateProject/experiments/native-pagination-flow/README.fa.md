# نمونهٔ مستقل جریان واقعی متن بین صفحات

این نمونه، ادامهٔ آزمایش مسیر رایگان روی Tiptap است؛ **جزء ادیتور اصلی محصول نیست و برای استفاده روی سند مشتری تأیید نشده است**. نتیجه و موانع: [گزارش فارسی](../../docs/research/native-pagination-flow.fa.md).

تفاوت با نمای کاغذی قبلی: ارتفاع ناحیهٔ متن محدود است و مرورگر محتوا را واقعاً به ستون بعدی می‌برد؛ هر ستون روی یک کاغذ جدا در نوار افقی قرار دارد. JSON هیچ گرهٔ صفحه یا فاصلهٔ ساختگی نمی‌گیرد. شماره‌ها، پس‌زمینه و سربرگ‌های نمونه خارج از ادیتور و فقط نمایشی‌اند. تعداد صفحه از چیدمان محاسبه می‌شود، نه از تعداد پاراگراف یا خط تخمینی.

## اجرای دستی

از ریشهٔ راه‌حل `EtranslateProject`، در PowerShell 7:

```powershell
./experiments/native-pagination-flow/Start-NativeFlow.ps1
```

بعد نشانی `http://127.0.0.1:5081/` را در مرورگر باز کنید. پایان با Ctrl+C. اسکریپت از Node همراه محیط فعلی استفاده می‌کند؛ در سیستم دیگر `-NodePath` را به Node سازگار بدهید. وابستگی‌های Web باید از قبل نصب باشند؛ این اسکریپت چیزی نصب نمی‌کند. AppHost و SQL لازم نیستند.

موارد قابل تست:

1. نمونهٔ فارسی/ترکی را باز کنید و از «Sayfaya git» به صفحهٔ دوم بروید. همان متن قابل ویرایش است؛ Undo/Redo را امتحان کنید.
2. در ابتدای سند متن طولانی وارد کنید؛ صفحات بیشتر می‌شوند. با Undo به چیدمان قبلی برگردید.
3. zoom و عرض پنجره را تغییر دهید؛ JSON و تعداد صفحات نباید تغییر کنند. در موبایل، اسکرول افقی داخل محدودهٔ کاغذ است.
4. «Salt okunur» را فعال کنید؛ جابه‌جایی صفحه همچنان مجاز است، اما تایپ نباید ممکن باشد. این فقط قفل آزمایش محلی است، نه تست نقش/اشتراک محصول.
5. سربرگ/پاورقی آخر، A5 افقی و جدول را باز کنید. در جدول بلند، عنوان ستون‌ها در ادیتور تکرار نمی‌شود؛ این **اختلاف حل‌نشده با PDF** است، نه رفتار مورد قبول محصول.
6. نمونهٔ سلول بلندتر از صفحه را باز کنید؛ صفحه‌بندی با هشدار خاموش می‌شود، متن باقی می‌ماند و شمارهٔ صفحهٔ جعلی نشان داده نمی‌شود.

در آزمون مرز صفحات، ابتدا به‌روزنشدن عدد صفحه مشاهده شد؛ سنجش دقیق‌تر عبور واقعی مکان‌نما را تأیید کرد. همگام‌سازی نما اصلاح و سه عبور مستقل در هر جهت با مختصات واقعی انتخاب و عدد UI بررسی شد. این نتیجه جای آزمون کامل صفحه‌کلید، IME و همهٔ داده‌ها را نمی‌گیرد. اختلاف عنوان جدول همچنان مانع شناخته‌شدهٔ اتصال به محصول است.

نمونه‌ها ثابت و ساختگی‌اند. چسباندن متن و رهاکردن فایل بسته است؛ هیچ دکمهٔ ذخیره، ورود سند، بارگذاری، پرداخت یا اتصال به API اصلی وجود ندارد. اجرای «Örneği aç» نمونهٔ جاری را بدون ذخیره جایگزین می‌کند؛ متن ارزشمند وارد نکنید.

## تست و مقایسهٔ چاپ

```powershell
./tests/ETranslate.EndToEndTests/Verify-NativePaginationFlow.ps1
```

چهار تست ورودی/هندسه/مرزبندی بسته‌ها و یک سناریوی مرورگر اجرا می‌شود. مرورگر Playwright باید از قبل در `.local/pdf-browsers` ریشهٔ مخزن موجود باشد. تست، سرور loopback با پورت تصادفی می‌سازد و در پایان می‌بندد؛ درخواست‌های خارجی مسدودند. PDFها با `ChromiumDraftPdfRenderer` موجود و بدون تغییر آن ساخته می‌شوند، سپس Python/pypdf نشانگرهای متن را صفحه‌به‌صفحه بررسی می‌کند.

نتایج در `tmp/pdfs/native-pagination-flow` و خارج از Git هستند:

- `browser-report.json`: دادهٔ مرورگر، انتقال متن، مکان‌نما و محدودیت‌ها.
- `pdf-comparison.json`: تطابق تعداد و صفحهٔ نشانگرها، با `productionApproved: false`.
- `native-flow.trx`: گزارش کامل آزمون.
- شش PDF ساختگی و تصاویر نمونه‌ها؛ **خروجی میانی QA هستند، نه مدارک نهایی**.

اگر یک اجرا شکست خورد، ابتدا گزارش همان اجرا را بررسی کنید؛ خروجی مانده از اجرای قبلی دلیل موفقیت اجرای جدید نیست. پاس‌شدن harness فقط یعنی آزمایش مطابق قرارداد اجرا شده است؛ به معنی رفع اختلاف جدول یا تأیید همهٔ شکست‌های خط و مرورگرها نیست.

## مرز کد

بستهٔ جدید نصب نمی‌شود. build فقط نسخه‌های دقیق `3.31.4` نصب‌شدهٔ Tiptap در Web و adapter فعلی را استفاده می‌کند. فایل‌های generated و کپی فونت‌ها با مجوزهای موجود در این پوشه ignore می‌شوند. schema، renderer، فایل‌های تولیدی Web، API، migration، دادهٔ ذخیره‌شده و PDF آرشیوی تغییر نکرده‌اند. سرور فقط مسیرهای صریح HTML/CSS/bundle/font را با GET/HEAD و Host محلی معتبر پاسخ می‌دهد؛ سایر روش‌ها و مسیرها رد می‌شوند. CSP به style/script خارجی اجازه نمی‌دهد؛ CSS قالب فقط از فایل محلی و تنظیم هندسه از کد قابل اعتماد آزمایش است.
