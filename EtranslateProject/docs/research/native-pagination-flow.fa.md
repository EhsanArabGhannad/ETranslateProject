# بررسی صفحه‌بندی با تقسیم بومی مرورگر

تاریخ: ۲۰۲۶-۱۰-۲۴

## تصمیم این قدم

نمونهٔ مستقل `experiments/native-pagination-flow` ساخته و با چاپگر فعلی آزمایش شد. نتیجه برای ادامهٔ مهندسی مسیر رایگان امیدوارکننده است؛ **هنوز به ادیتور اصلی متصل یا برای محصول تأیید نشده است**. برخلاف آزمایش قبلی Pagination Plus، این نمونه هیچ paginator و قرارداد جدول جدیدی ندارد و JSON فعلی را تغییر نمی‌دهد.

مدل CSS چندستونی با ارتفاع ثابت، ستون‌های سرریز را در جهت افقی ایجاد می‌کند؛ این مبنای فنی، نه تضمین صحت ادیتور یا همسانی چاپ، در [استاندارد CSS Multi-column](https://www.w3.org/TR/css-multicol-1/) توضیح داده شده است. صحت این پیاده‌سازی فقط از آزمون محلی زیر نتیجه می‌شود، نه از ادعای استاندارد یا نام مرورگر.

## نتایج اندازه‌گیری‌شده

| نمونه | صفحهٔ ادیتور / PDF | شواهد و محدودیت |
| --- | --- | --- |
| متن فارسی/ترکی | ۴ / ۴ | ۴۸ نشانگر یکتا، بدون افت متن نشانگر و بدون اختلاف صفحهٔ آن‌ها. |
| سربرگ + پاورقی فقط آخر | ۴ / ۴ | همان ۴۸ نشانگر هم‌صفحه؛ رزرو هندسهٔ سربرگ/پاورقی مطابق قواعد چاپ اندازه‌گیری شد. سربرگ روی همه و پاورقی روی آخرین کاغذ نمونه نمایش داده شد. |
| A5 افقی با حاشیهٔ نامتقارن | ۷ / ۷ | هر ۴۸ نشانگر در همان صفحهٔ PDF بودند. |
| سند شامل جدول ساده | ۳ / ۳ | schema و متن ادیتور حفظ شد؛ این نمونه نشانگر یکتای صفحه ندارد، پس از آن تطابق محل متن نتیجه نمی‌گیریم. |
| جدول ۴۶ ردیفی | ۶ / ۶ | ۴۶ نشانگر ردیف و نشانگر انتهای جدول هم‌صفحه بودند؛ **عنوان جدول در صفحه‌های بعدی ادیتور تکرار نمی‌شود، ولی در PDF می‌شود**. تطابق صفحهٔ نشانگرها این اختلاف بصری را رد نمی‌کند. |
| یک پاراگراف بلند | ۳ / ۳ | نشانگر ابتدا در صفحهٔ ۱ و انتها در صفحهٔ ۳ در هر دو خروجی؛ تمام شکست‌های خط میانی هنوز اثبات نشده‌اند. |
| سلول بلندتر از ناحیهٔ چاپ | صفحه‌بندی خاموش / PDF رد شد | همان محدودیت فعلی renderer تشخیص داده شد؛ متن حفظ شد، یک سطح پیوسته ماند و تکثیر بی‌رویهٔ صفحات مشاهده نشد. این پشتیبانی از سلول بلند نیست. |

افزودن واقعی متن با صفحه‌کلید در ابتدای سند، نمونهٔ ۴ صفحه‌ای را به ۱۰ صفحه رساند؛ Undo همان JSON و ۴ صفحه را برگرداند. تایپ و Undo/Redo در صفحهٔ دوم، جابه‌جایی با انتخاب شمارهٔ صفحه، zoom در ۷۵/۱۰۰/۱۲۵ درصد، عرض ۳۹۰ پیکسل و ناوبری در قفل فقط‌خواندنی آزمایش شدند. تغییر نما JSON را تغییر نداد. یک نمونهٔ DOM ادیتور حفظ شد؛ سند برای ساخت صفحات به چند editor یا چند پاراگراف مصنوعی تبدیل نشد.

آزمون تکمیلی: کلیک و تایپ در پاراگراف فارسی صفحهٔ دوم و Undo، همان JSON اولیه را برگرداند. در یک اجرای اولیه، شاخص UI پس از فلش پایین روی صفحهٔ ۱ ماند؛ ابتدا این را نشانهٔ عبورنکردن مکان‌نما تلقی کردیم. سنجش مستقلِ مختصات انتخاب، عبور واقعی به صفحهٔ ۲ را نشان داد؛ عدد UI به‌تنهایی معیار کافی نبود. همگام‌سازی نما پس از keyup ناوبری اضافه شد، بدون حرکت‌دادن انتخاب یا transaction محتوا. سپس سه عبور مستقل پایین از پایان صفحهٔ اول و سه عبور بالا از ابتدای صفحهٔ دوم، هم مختصات واقعی مکان‌نما و هم عدد UI را پاس کردند. اطلاعات هر تکرار در `NativeArrowDown` و `NativeArrowUp` ثبت شده است؛ مشاهدهٔ اولیه پاک یا به‌عنوان شکست قطعیِ موتور گزارش نمی‌شود. این پوشش محدود با «پشتیبانی کامل فارسی/RTL» یکی نیست.

ظاهر فارسی/ترکی و شکست صفحه‌ها در تصاویر ادیتور و رندر Poppler از PDFهای ساختگی بازبینی شد. این بازبینی، ممیزی کامل BiDi، همهٔ فونت‌ها، همهٔ سطرها یا همهٔ داده‌های ممکن نیست. تصاویر/PDFها فقط شواهد میانی توسعه‌اند، نه سند مشتری یا خروجی حقوقی.

## حفاظت و حدود اثبات

- adapter و provider فعلی محصول بدون تغییر استفاده شدند؛ API، schema v1، renderer/version چاپ و فایل‌های تولیدی Web تغییر نکردند.
- شمارش بر اساس overflow واقعیِ ستون‌ها و مختصات متن است. کاغذها و سربرگ‌های ثابت نمونه بیرون از DOM ادیتور و خارج از JSON هستند.
- اندازه، حاشیه‌ها و ذخیرهٔ ۸ میلی‌متری شمارهٔ PDF همان قواعد renderer فعلی‌اند. فونت‌ها همان فایل‌های Noto پروژه‌اند؛ CSS تایپوگرافی آزمایش با چاپ همسو شده است، اما قرارداد مشترک تولیدی برای جلوگیری از drift آینده هنوز ساخته نشده است.
- سقف ۵۰ صفحه و تشخیص ردیف بیش از اندازه fail-closed هستند؛ هشدار به معنی موفقیت صفحه‌بندی نیست.
- سرور فقط loopback، مسیرهای allowlist و GET/HEAD دارد. POST و مسیرهای خارج از فهرست رد شدند؛ درخواست خارجی و خطای مرورگر در اجرای کامل مشاهده نشد.
- هیچ خرید، حساب، بستهٔ جدید، SQL، AppHost، API اصلی، مدرک واقعی یا دستکاری PDF آرشیوی انجام نشد.

## قبل از اتصال به محصول چه مانده؟

1. هماهنگ‌کردن DOM جدول و تکرار واقعی عنوان آن با چاپ؛ بدون حذف داده، عوض‌کردن schema درجا یا کپی نمایشی‌ای که انتخاب/مکان‌نما را خراب کند.
2. پوشش دقیق‌تر مکان‌نما و انتخاب در مرز خط/صفحه، سلول و فهرست؛ پاک‌کردن و بازگشت متن، IME، موبایل واقعی و مرورگرهای هدف. نتیجهٔ جزئیات آزمون جهت‌ها در گزارش اجرای محلی ثبت می‌شود.
3. یک قرارداد قابل نگهداری برای تایپوگرافی و رزرو فضای قالب؛ CSS آزمایش نباید جدا از چاپ drift کند. تصاویر/لوگوهای خصوصی، قالب واقعی، watermark و حالت‌های حاشیه/اندازهٔ بیشتر به پوشش مستقل نیاز دارند.
4. آزمون ذخیره/بازخوانی، قفل‌های نقش/اشتراک/بازبینی و نسخهٔ تاریخی با صفحه‌بندی فعال در خود محصول؛ استفاده از همان adapter به‌تنهایی اثبات این یکپارچگی نیست.
5. تصمیم دربارهٔ نمای افقیِ صفحات یا ارائهٔ یک صفحه در هر نوبت؛ نمونه فعلاً نوار افقی با انتخاب شماره دارد. شکست صفحهٔ دستی به قرارداد نسخه‌دار جدا نیاز دارد و در این قدم اضافه نشده است.

در نتیجه، ادامهٔ مناسب همین شاخهٔ بدون وابستگی جدید است، با تمرکز بعدی روی جدول و پوشش بیشتر مرز مکان‌نما؛ نه فعال‌کردن عمومی و نه اعلام برابری کامل با Word/PDF. در این قدم چهار تست آزمایشگاه و سناریوی مرورگر/مقایسهٔ شش PDF تکمیل شدند؛ اختلاف عنوان جدول همچنان حل نشده است. رگرسیون عادی ۵۳۵ تست Domain و دو تست Architecture و ۶۲ تست کلاینت را پاس کرد؛ ۲۷ تست وابسته به محیط در Domain و یک placeholder سراسری skip ماندند. در اجرای عادی، آزمایش جدید بدون opt-in اجرا نمی‌شود.

## بازتولید

[راهنمای اجرا و تست نمونه](../../experiments/native-pagination-flow/README.fa.md). خروجی اجرای کامل در `tmp/pdfs/native-pagination-flow` است و در Git نگهداری نمی‌شود. مقایسهٔ Python وجود یکتای نشانگرها را الزامی می‌کند، اما اختلاف صفحه را به‌عنوان یافته ثبت می‌کند؛ پاس‌شدن اسکریپت، تأیید کیفیت موتور نیست. تنها گزارشی معتبر است که مرحلهٔ مرورگر و مقایسهٔ همان اجرا کامل شده باشند.
