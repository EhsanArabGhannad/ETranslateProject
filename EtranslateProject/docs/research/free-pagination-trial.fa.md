# آزمایش عملی گزینهٔ رایگان صفحه‌بندی

تاریخ: ۲۰۲۶-۱۰-۲۰

تکمیل بعدی: آزمایش Canvas Editor اکنون انجام شده است؛ وضعیت جدید و ادامهٔ پیشنهادی در [گزارش Canvas](canvas-editor-trial.fa.md) ثبت شده‌اند. متن این گزارش نتایج آزمایش قبلی را حفظ می‌کند.

## تصمیم فعلی

`Tiptap 3.31.4 + tiptap-pagination-plus 3.1.0 + tiptap-table-plus 3.1.0` در محیط مستقل اجرا شد. **این ترکیب در وضعیت آزمایش‌شده برای اتصال مستقیم به محصول تأیید نمی‌شود.** ویرایش متن معمولی قابل استفاده بود، اما سه مانع روشن داریم: اختلاف مرز صفحه با PDF، تغییر قرارداد جدول، و رشد ناپایدار صفحات در سلول بلند.

این نتیجه دربارهٔ همین نسخه‌ها، fixtures و تنظیمات است؛ حکم کلی علیه Tiptap یا همهٔ گزینه‌های رایگان نیست. موتور، ذخیره‌سازی و چاپ‌گر اصلی پروژه تغییر نکرده‌اند. نمونهٔ فقط‌خواندنی قبلی نیز حفظ شده است. [راهنمای اجرای نمونهٔ جدید](../../experiments/tiptap-pagination-free/README.fa.md)

## آنچه واقعاً آزمایش شد

| مورد | مشاهدهٔ محلی |
| --- | --- |
| متن فارسی/ترکی | ۴ صفحهٔ قابل ویرایش؛ همهٔ ۴۸ نشانگر متن حفظ شدند؛ JSON متن ساده با validatorهای فعلی JavaScript و C# سازگار ماند. نمایش فارسی و حروف ترکی در نمونهٔ تصویری بررسی شد؛ پوشش جامع BiDi هنوز ادعا نمی‌شود. |
| تایپ و جابه‌جایی | کلیک و تایپ با صفحه‌کلید در پاراگراف‌های صفحات اول و دوم، Undo/Redo، پرش به صفحهٔ دوم بدون تغییر JSON و بازخوانی JSON در حافظهٔ همان تب پاس شدند. ذخیرهٔ پایدار/API آزمایش نشده است. |
| جریان متن | افزودن ۴۰ پاراگراف در ابتدای سند، ۴ صفحه را به ۶ رساند؛ Undo، JSON اولیه و ۴ صفحه را برگرداند. |
| بزرگ‌نمایی و عرض باریک | در ۷۵/۱۰۰/۱۲۵ درصد JSON و selection ثابت ماندند؛ تعداد همان ۴ صفحه بود. در عرض ۳۹۰ پیکسل، کاغذ اسکرول داخلی داشت و صفحهٔ وب بیرون نزد. |
| PDF مرجعِ چاپ‌گر فعلی | تعداد هر دو خروجی ۴ صفحه شد، ولی ۴ نشانگر شروع پاراگراف در صفحهٔ متفاوت افتادند؛ بنابراین تطابق صفحه رد شد. این آزمون تعداد صفحه را به‌جای وفاداری چاپ جا نمی‌زند. |
| جدول ساده و جدول ۴۶ ردیفی | متن حفظ شد؛ جدول بلند در نمونه ۵ صفحه شد، ولی `table.columnSize` اضافه شد و validator و renderer فعلی خروجی را رد کردند. کیفیت تکرار عنوان همهٔ صفحات جدول هنوز تأیید نشده است. |
| سلول ادغام‌شده | افزونه `tableRowGroup` ساخت؛ قرارداد فعلی آن و rowspan را نمی‌پذیرد. چیدمان و دستگیره‌های تغییر اندازه هم نیازمند بررسی بیشترند؛ نمایش اولیه به معنی سازگاری محصول نیست. |
| سلول بلندتر از صفحه | پس از اندازه‌گیری واقعی، تعداد صفحات پیوسته رشد کرد؛ در اجرای بدون محافظ، ۴۷۸ صفحه پس از حدود ۱۰ ثانیه مشاهده و تست رد شد. محافظ مستقل آزمایش در اجرای نهایی با عبور از آستانهٔ ۵۰، صفحه‌بندی را خاموش کرد، هشدار نشان داد و متن را نگه داشت؛ این نمونه از نظر کیفیت موتور **شکست‌خورده** است. |
| پاراگراف بلندتر از صفحه | متن حفظ و ۳ صفحه در نمونه ایجاد شد؛ آزمون همهٔ شکست‌های خط و تطابق PDF این حالت هنوز انجام نشده است. |
| HTML شبیه Word | همچنان فونت، اندازه، رنگ، تراز، فاصلهٔ خطوط و هایلایت در تنظیم پایه حفظ نشدند. افزونهٔ صفحه‌بندی واردکنندهٔ Word نیست. Clipboard واقعی و DOCX واقعی آزمایش نشده‌اند. |

مقایسهٔ نشانگرها در اجرای مرجع:

| نشانگر | صفحهٔ ادیتور | صفحهٔ PDF |
| --- | --- | --- |
| `MARK_015` | ۱ | ۲ |
| `MARK_030` | ۲ | ۳ |
| `MARK_045` | ۳ | ۴ |

تمام متن نشانگرها در PDF باقی ماند؛ آزمون تطابق محل، نه آزمون از دست رفتن متن، شکست خورد. اختلاف اندازه‌گیری‌شده رفع نشده و علت دقیق همهٔ تفاوت‌ها هنوز اثبات نشده است. PDF و تصاویر فقط خروجی میانی QA با دادهٔ ساختگی‌اند، نه مدرک قابل استفاده برای مشتری.

## مرز کد و حفاظت

- وابستگی‌ها فقط در `experiments/tiptap-pagination-free` نصب شده‌اند؛ نسخه‌ها دقیق و lockfile دارای integrity است؛ install scripts اجرا نشدند.
- build، همان موتور و یک نمونهٔ ProseMirror نصب‌شدهٔ Web را استفاده می‌کند. package و lockfile اصلی، JSON قرارداد، renderer، migration و اسناد قدیمی تغییر نکرده‌اند.
- برای اعمال اندازه‌گیری اولیه، پس از آماده‌شدن فونت/CSS، یک transaction بدون history فرستاده می‌شود؛ بدون این راه‌اندازی، شمارش اولیهٔ نمایش قابل اتکا نبود. کد منتشرشدهٔ افزونه patch نشده است.
- watchdog با زمان‌بندی مستقل از debounce به نمونه اضافه شد؛ توقف رشد بی‌رویه یک حفاظت آزمایشگاهی است، نه برطرف‌شدن ایراد کتابخانه. متن در حافظه حفظ می‌شود، ولی هنوز ذخیرهٔ پایدار نداریم.
- نیاز افزونه به styleهای درون‌صفحه‌ای فقط در CSP نمونه مجاز شده؛ برای محصول نیاز به راه‌حل سازگار با سیاست امنیتی موجود داریم. header/footer با `innerHTML` ساخته می‌شوند و در نمونه فقط رشته‌های ثابت‌اند.
- هیچ درخواست خارجی در آزمون مرورگر مشاهده نشد؛ سرور loopback با فهرست فایل‌های مجاز و بدون POST است. هیچ سند واقعی، خرید، حساب یا سرویس تجاری استفاده نشد.

## آزمون‌های انجام‌شده

۶ آزمون fixture/bundle، یک آزمون مرورگر و بررسی متن PDF با pypdf اجرا شدند؛ همهٔ چک‌های harness پاس شدند، اما **کیفیت موتور عمداً تأیید نشده** و شکست‌ها در گزارش ثبت‌اند. ۵۰۸ آزمون عادی .NET و ۴۵ آزمون JavaScript موجود نیز پاس شدند؛ آزمون‌های وابسته به محیط در اجرای عادی همچنان skip می‌شوند.

گزارش‌های توسعه در `tmp/free-pagination` هستند: `browser-report.json`، `pdf-comparison.json`، تصاویر و PDF مرجع. برای بازتولید از `Verify-FreePagination.ps1` استفاده کنید. نتیجهٔ آزمون ناموفق را با گزارش قدیمی یک اجرای قبلی اشتباه نگیرید؛ فقط خروجی اجرای تکمیل‌شدهٔ موفق harness مبنای این جمع‌بندی است.

## ادامهٔ پیشنهادی

پیشنهاد مهندسی فعلی: **پیش از صرف هزینه برای اصلاح عمیق این افزونه یا تغییر قرارداد محصول، Canvas Editor را با همین معیارها در نمونهٔ مستقل آزمایش کنیم.** این پیشنهاد به معنی تأیید فارسی، PDF یا Word در Canvas Editor نیست؛ آن موتور هنوز نصب یا آزمایش نشده است.

اگر بخواهیم همین شاخه را ادامه دهیم، کار جداگانه لازم است: بازتولید حداقلی و رفع رشد صفحات سلول بلند، adapter/نسخه‌بندی بدون حذف بی‌هشدار ویژگی‌های جدول، تطبیق واقعی شکست‌های خط/پاراگراف با چاپ، و حل CSP/HTML امن. هیچ‌کدام با مخفی‌کردن هشدار، حذف `columnSize` یا قبول همیشگی JSON در validator حل نمی‌شوند.

قالب‌های واقعی، پابرگ فقط صفحهٔ آخر، تصاویر خصوصی، import/paste Word و آزمون سراسری ثبت پرونده پس از عبور موتور از این دروازه‌ها می‌آیند؛ در این قدم پیاده نشده‌اند.
