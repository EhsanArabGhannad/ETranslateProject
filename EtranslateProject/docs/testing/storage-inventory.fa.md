# گزارش تطبیق فایل‌ها با دیتابیس

تاریخ: ۲۰۲۶-۱۱-۰۴

## چه چیزی اضافه شد؟

ابزار مدیریتی `ETranslate.StorageAudit` اطلاعات ثبت‌شده در SQL Server را با فایل‌های پوشهٔ ذخیره‌سازی مقایسه و گزارش JSON تولید می‌کند. فایل مبدا، تصویر داخل ترجمه، تصویر قالب، PDF پیش‌نویس و پیش‌نمایش امضا پوشش دارند. نسخه‌های قدیمی، تصویرهای نگهداری‌شده‌ای که در متن فعلی نیستند و قالب‌های غیرفعال نیز حساب می‌شوند.

این ابزار جدا از سایت اجرا می‌شود. اجرای آن سرویس یا migration راه نمی‌اندازد و فایل‌های ذخیره‌سازی یا اطلاعات دیتابیس را اصلاح و حذف نمی‌کند. فقط گزارش تازه‌ای در مسیر انتخاب‌شده می‌نویسد؛ قابلیت تازه‌ای به پنل کاربران اضافه نشده است.

## معنی وضعیت‌ها

| وضعیت گزارش | معنی و اقدام |
|---|---|
| `Verified` | حجم و SHA-256 فایل با اطلاعات ثبت‌شده برابر است. |
| `Missing` | رکورد وجود دارد و مسیر فایل در زمان بررسی پیدا نشد؛ نیاز به بررسی و بازیابی دارد. |
| `SizeMismatch` | حجم فعلی با حجم ثبت‌شده فرق دارد. |
| `HashMismatch` | حجم برابر است، اما بایت‌ها با هش ثبت‌شده تطابق ندارند. |
| `MetadataConflict` | چند رکورد برای یک کلید، اطلاعات حجم/هش متفاوت دارند. |
| `UnreferencedRecent` | فایل در رکوردهای خوانده‌شده نیست و زمان آخرین تغییرش تازه‌تر از آستانه است. ممکن است عملیات هنوز تمام نشده باشد. |
| `UnreferencedAged` | فایل ارجاع مشاهده‌شده ندارد و زمان آخرین تغییرش قدیمی‌تر است؛ این وضعیت مجوز حذف نیست. |
| `TemporaryRecent` / `TemporaryAged` | فایل موقت `.uploading`؛ محتوا باز و هش نمی‌شود. |
| `ReferenceUnknown` | خواندن رکوردها به سقف رسیده است؛ دربارهٔ بدون‌رکوردبودن این فایل نتیجه نمی‌گیریم. |
| `Unverifiable` / `UnsafePath` | خواندن ممکن نبود یا مسیر پیوندی/junction بود؛ گزارش کامل نیست. |
| `InvalidKey` / `InvalidMetadata` | مسیر یا مشخصات ثبت‌شده نامعتبر است. |
| `HashLimit` / `ChangedDuringRead` | سقف بررسی هش پر شد یا فایل هنگام بررسی تغییر کرد؛ نتیجهٔ کامل تأیید نشده است. |

`complete=true` یعنی بررسی طبق سیاست و محدودهٔ تعیین‌شده تمام شده، نه اینکه همهٔ فایل‌ها سالم‌اند. برای نتیجهٔ کلی، `hasFindings`، `counts`، `issues` و وضعیت هر ردیف را هم ببینید. هر ردیف شناسه/نوع رکورد، کلید فایل، حجم و هش مورد انتظار و در صورت بررسی موفق، حجم/هش واقعی و زمان آخرین تغییر را دارد.

## تست انجام‌شده

اجرای نهایی: `4e03902f84c74cfa93549e56452fed69`.

- **۲۸ تست مستقل** برای فایل سالم، فایل مشترک بین ارجاع‌ها، فایل مفقود، مغایرت حجم/هش، فایل قفل‌شده، سن فایل‌ها، فایل موقت قفل‌شده، محدودیت شمار/حجم، مسیر نامعتبر یا پوشه به‌جای فایل، لغو و جلوگیری از بازنویسی گزارش.
- یک مجموعهٔ SQL با **هشت بررسی گروهی**: خواندن هر پنج نوع دارایی با حساب دارای SELECT و منع نوشتن، حفظ ارجاع‌های تاریخی، شمار/وضعیت دقیق، اجرای واقعی ابزار، جلوگیری از بازنویسی، گزارش ناقص، junction واقعی ویندوز و حفظ اطلاعات/فایل‌ها.
- شش دیتابیس QA تازه ساخته و حذف شدند؛ فقط دیتابیس مدارک در این تست استفاده شد. هیچ دیتابیس محصول یا مدرک کاربر خوانده نشد.
- پیش و پس از اسکن، اطلاعات ثبت‌شده و پیش‌نویس/بازبینی و همچنین بایت‌ها، حجم و زمان آخرین تغییر فایل‌ها یکسان بودند.
- ساخت پروژه بدون خطا و هشدار بود. اجرای معمول solution نیز **۷۶۵ تست Domain و دو تست معماری** را گذراند؛ ۷۸ تست اختیاری Domain و یک placeholder قدیمی E2E در اجرای معمول غیرفعال‌اند.

گزارش ساختگی این اجرا ۱۲ ردیف دارد:

| نتیجه | تعداد |
|---|---:|
| سالم | ۵ |
| مفقود | ۱ |
| مغایرت حجم | ۱ |
| مغایرت هش با حجم برابر | ۱ |
| بدون ارجاعِ تازه / قدیمی | ۱ / ۱ |
| موقتِ تازه / قدیمی | ۱ / ۱ |

[مشاهدهٔ نمونهٔ JSON آزمایش](../../tmp/pdfs/storage-inventory/4e03902f84c74cfa93549e56452fed69/inventory.json). داده‌ها ساختگی‌اند؛ برچسب PDF در fixture برای آزمون ذخیره‌سازی است و این قدم خروجی PDF یا امضای واقعی تولید/اعتبارسنجی نمی‌کند. دیتابیس نمونه پس از تست پاک شده؛ فایل گزارش برای مشاهده باقی است.

## اجرای دوبارهٔ تست ایزوله

از پوشهٔ solution:

```powershell
pwsh -NoProfile -File ./tests/ETranslate.EndToEndTests/Verify-StorageInventory.ps1 -SqlServer '.\ESIMSSQLSERVER'
```

اسکریپت از .NET 10، SQL Server محلی و PowerShell 7 استفاده می‌کند. حساب اجرای تست به اجازهٔ ساخت و حذف دیتابیس QA نیاز دارد؛ ابزار عملیاتی گزارش‌گیری چنین اجازه‌ای لازم ندارد. گزارش‌های `acceptance.json` و `cleanup.json` زیر `tmp/pdfs/storage-inventory/<run>` هستند. `cleanupSucceeded` باید درست و `existingDatabasesUsed` نادرست باشد.

اگر پروژه تازه دریافت شده است، ابتدا وابستگی‌های موجود solution را restore کنید. تست، فایل تنظیمات یا SQL Server کاربر را تغییر نمی‌دهد؛ ساخت/حذف فقط برای نام‌های تازه و متعلق به همان اجرای QA است.

## استفادهٔ مدیریتی از ابزار

نام دیتابیس مدارک و **کل پوشهٔ ذخیره‌سازی همان دیتابیس** را از تنظیمات استقرار انتخاب کنید؛ زیرپوشهٔ یک مشتری یا مسیر حدسی، گزارش درستی از کل دیتابیس نمی‌دهد. اتصال را با حساب فقط‌خواندنی دارای SELECT روی جدول‌های سرویس مدارک اجرا کنید. `ApplicationIntent=ReadOnly` به‌تنهایی دسترسی نوشتن حساب را لغو نمی‌کند.

نمونهٔ زیر نیاز به جایگزینی نام دیتابیس و دو مسیر نمونه دارد. پوشهٔ گزارش باید قبلاً وجود داشته باشد و بیرون از پوشهٔ ذخیره‌سازی باشد. ابزار مسیر موجود گزارش را بازنویسی نمی‌کند.

```powershell
$env:ETRANSLATE_AUDIT_CONNECTION = 'Server=.\ESIMSSQLSERVER;Database=YOUR_DOCUMENTS_CATALOG;Integrated Security=True;Encrypt=True;TrustServerCertificate=True'
dotnet ./src/Tools/ETranslate.StorageAudit/bin/Debug/net10.0/ETranslate.StorageAudit.dll `
  --connection-env ETRANSLATE_AUDIT_CONNECTION `
  --storage-root 'D:\Data\ETranslate\document-blobs' `
  --output 'D:\ETranslateReports\audit-20261104-01.json'
```

رشتهٔ اتصال آرگومان خط فرمان نیست و داخل گزارش چاپ نمی‌شود. گزارش شامل نام سرور/دیتابیس، مسیر انتخاب‌شده و کلیدها و شناسه‌های داخلی است؛ دسترسی به آن باید مدیریتی بماند. گزارش‌گیری مجوز دسترسی مستأجر در پنل سایت ایجاد نمی‌کند.

| کد پایان ابزار | معنی |
|---|---|
| `0` | بررسی کامل، بدون یافته |
| `1` | بررسی کامل، دارای یافته؛ وجود گزارش لزوماً خطای اجرای ابزار نیست |
| `2` | گزارش ناقص؛ محدودیت‌ها و وضعیت‌ها را ببینید |
| `3` | خطای تنظیمات/دسترسی/اجرا؛ گزارش کامل تأیید نشده است |
| `130` | لغو یا پایان مهلت؛ گزارش کامل تأیید نشده است |

پیش‌فرض‌ها: آستانهٔ تازگی ۲۴ ساعت، سقف ۱۰۰هزار ورودی فایل‌سیستم شامل پوشه‌ها، ۱۰۰هزار ارجاع دیتابیس، ۲۵ MiB برای هش هر فایل، مجموع رزرو هش ۱ GiB و مهلت لغو ۳۰۰ ثانیه. اندازهٔ فایل‌های معمول محصول در این محدوده است؛ فایل بزرگ‌تر با `HashLimit` گزارش می‌شود. محدودیت‌ها با `--help` قابل مشاهده‌اند. لغو برای عملیات پشتیبانِ آن اعمال می‌شود و تضمین قطع فوری عملیات همگام سیستم‌عامل نیست.

اگر ساخت گزارش لغو شود یا نوشتن آن شکست بخورد، ممکن است JSON ناقص باقی بماند. تنها JSON معتبر همراه نتیجهٔ تأییدشدهٔ اجرا را مبنا قرار دهید؛ گزارش ناقص را با فهرست سلامت کامل اشتباه نگیرید.

## حدود این گزارش

گزارش یک مشاهده در بازهٔ زمان است؛ SQL و فایل‌سیستم snapshot اتمیک مشترک ندارند. آپلود ممکن است بعد از خواندن رکوردها تمام شود. سن نمایش‌داده‌شده از آخرین تغییر فایل محاسبه می‌شود و سن قطعی عملیات یا دلیل قابل‌حذف‌بودن نیست.

مسیرهای پیوندیِ مشاهده‌شده دنبال نمی‌شوند؛ پوشه باید تحت کنترل مدیر باشد. بررسی روی ذخیره‌ساز محلی ویندوز انجام شده و پذیرش object storage، دست‌کاری خصمانهٔ هم‌زمان مسیرها، قطع فرایند یا پشتیبان‌گیری نیست. برابری هش فقط تطابق بایت با رکورد را می‌سنجد؛ اعتبار حقوقی یا e-imza را تأیید نمی‌کند.

هیچ گزینهٔ حذف، ترمیم یا قرنطینه اضافه نشده است. قدم بعدی پیشنهادی، آزمون پشتیبان‌گیری و بازیابی در محیط جداست. [ADR 0053](../adr/0053-read-only-managed-storage-inventory.md) تصمیم فنی و [قدم حفاظت از فایل](storage-failure-recovery.fa.md) علت نگهداری فایل‌های دارای ثبت نامعلوم را توضیح می‌دهد.
