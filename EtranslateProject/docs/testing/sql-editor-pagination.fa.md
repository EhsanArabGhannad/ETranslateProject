## محدوده

این آزمون شش برنامهٔ اصلی Identity، Billing، Workflow، Documents، Trust و Web را با باینری Debug اجرا می‌کند. پاسخ ذخیره، ورود، مجوز دسترسی، اشتراک، بازبینی و PDF ساختگی نیست؛ مسیر واقعی Web/BFF و سرویس‌ها استفاده می‌شود. فقط حساب و اسناد داخل آزمون ساختگی‌اند.

برای هر اجرا شش دیتابیس تازه با نام `ETranslatePaginationQa_<runId>_<service>` ساخته می‌شوند. اتصال فقط به instance محلی، با هویت Windows است؛ انتخاب نام دیتابیس، اتصال راه دور یا درج رمز SQL مجاز نیست. تنظیمات اتصال همهٔ برنامه‌های فرزند به دیتابیس‌های همان اجرا بازنویسی می‌شود؛ appsettings، user-secrets و دیتابیس‌های فعلی پروژه تغییر نمی‌کنند. AppHost، Gateway، نوتر، پرداخت و سرویس خارجی اجرا نمی‌شوند.

در پایان، فقط فرایندهای ساخته‌شده توسط آزمون بسته و فقط دیتابیس‌هایی که همین اجرا ساخته حذف می‌شوند. کنترل مالکیت و نام کامل پیش از حذف الزامی است؛ دیتابیس از پیش موجود هرگز برای آزمون بازاستفاده یا پاک نمی‌شود. فایل‌های ساختگی و گزارش‌ها برای بررسی در `tmp/pdfs/sql-pagination/<runId>/` باقی می‌مانند و داخل Git نیستند.

## اجرا

پیش‌نیازها: SQL Server محلی با اجازهٔ ایجاد/حذف دیتابیس آزمایشی، .NET 10، وابستگی‌های از قبل بازیابی‌شده، Chromium Playwright و Node/Python موجود با pypdf. هیچ نصب یا خرید خودکار انجام نمی‌شود.

از ریشهٔ راه‌حل در PowerShell 7:

```powershell
./tests/ETranslate.EndToEndTests/Verify-SqlPagination.ps1 -SqlServer '.\ESIMSSQLSERVER'
```

نام instance محلی را متناسب با سیستم خود بدهید. اسکریپت ابتدا bundle و راه‌حل را می‌سازد، سپس آزمون اختیاری را فعال می‌کند. اجرای معمول `dotnet test` این آزمون SQLدار را skip می‌کند. پورت‌ها برای هر اجرا جدا و فقط روی loopback هستند؛ برنامه‌های در حال اجرای کاربر متوقف نمی‌شوند. هزینهٔ اشتراک، ارسال واقعی پیام یا سند مشتری در کار نیست؛ ایجاد اشتراک آزمایشی از رویداد واقعی SQL transport استفاده می‌کند.

## چه چیزهایی بررسی می‌شوند؟

- ثبت حساب از رابط واقعی، ورود مرورگر، ایجاد فضای کاری و دریافت اشتراک آزمایشی از Billing؛ آزمون رمز کوتاه و نمایش پیام بدون بازنمایش رمز.
- سه پرونده: جدول بدون عنوان و بدون قالب؛ جدول عنوان‌دار با قالب سادهٔ ساخته‌شده از فرم قدیمی؛ جدول با ردیف اول ترکیبی و سربرگ تصویری با تراز راست و پاورقیِ فقط صفحهٔ آخر.
- ویرایش در صفحهٔ دوم، Undo/Redo، ذخیره از دکمهٔ اصلی، خواندن دوباره از API و مرورگر، descriptor نسخهٔ ۱ و حفظ دقیق JSON نسخهٔ قبل.
- ساخت PDF از دکمهٔ واقعی، دانلود از Web/BFF، تطابق SHA-256 و نوع فایل/هدرهای دریافت، کش خروجی همان نسخه و تطابق صفحهٔ تک‌تک نشانگرها با DOM ادیتور.
- ایجاد یک PDF آرشیویِ ساختگی با metadata چاپگر v10 در دیتابیس تازه؛ اتصال بازبینی به آن، سپس تولید v11 برای **همان نسخهٔ سند**؛ هویت و هش فایل قبلی و مرجع PDF در بازبینی باید ثابت بمانند. این fixture به معنی اجرای موتور قدیمی v10 یا آزمودن آرشیو مشتری نیست.
- قفل واقعی بازبینی و نسخهٔ تاریخی؛ ناوبری صفحه باید فعال باشد، تایپ/فرمان‌ها و ذخیره غیرفعال بمانند و نوشتن مستقیم API در وضعیت قفل‌شده با 409 رد شود.
- رد دانلود بدون احراز هویت و دسترسی به مسیر مستأجر دیگر؛ نبود درخواست خارجی، خطای JavaScript و نقض CSP در مسیرهای آزموده‌شده.
- تکرار سربرگ، پاورقی همهٔ صفحات و پاورقی فقط آخر، هم در ادیتور و هم از متن استخراج‌شدهٔ PDF.

## گزارش‌ها

| فایل | کاربرد |
| --- | --- |
| `tmp/sql-pagination/sql-pagination.trx` | نتیجهٔ آزمون دات‌نت |
| `tmp/sql-pagination/latest.json` | شناسهٔ آخرین اجرای موفق مرورگر؛ موفقیت نهایی PDF را از گزارش بعدی بخوانید |
| `tmp/pdfs/sql-pagination/<runId>/browser-report.json` | سناریوها، تعداد صفحات و محدودهٔ fixture آرشیو |
| `…/pdf-comparison.json` | بررسی مستقل PDF با Python؛ نتیجهٔ نهایی باید `passed: true` باشد |
| `…/browser-errors.json` | خطاهای مرورگر، درخواست خارجی و CSP؛ باید خالی باشند |
| `…/cleanup.json` | نتیجهٔ حذف شش دیتابیس متعلق به همان اجرا |
| `…/*.log` | لاگ شش برنامهٔ موقت؛ رمز و توکن در گزارش آزمون چاپ نمی‌شوند |
| `…/*.pdf` و `…/*-markers.json` | PDF دریافت‌شده و جای واقعی نشانگرهای ادیتور |
| `…/*.png` و `…/*-footer.png` | تصاویر محصول برای بررسی ناحیهٔ صفحه و پاورقی |

اگر آزمون شکست خورد، ابتدا TRX، پوشهٔ همان اجرا و `cleanup.json` را بررسی کنید؛ گزارش موفق اجرای قبلی را نتیجهٔ اجرای ناموفق حساب نکنید. این آزمون هیچ دیتابیس یا فایل عملیاتی را برای cleanup هدف نمی‌گیرد.

## اصلاح‌های حاصل از پذیرش واقعی

نتیجهٔ اجرای کامل روی SQL Server محلی نسخهٔ ۱۶ و Chromium ثابت مخزن: هر سه پرونده پاس شدند؛ تعداد صفحات به‌ترتیب ۶، ۶ و ۷ بود و صفحهٔ هر ۱۴۱ نشانگر با PDF مطابقت داشت. CSP و خطاهای مرورگر خالی بودند؛ حفظ آرشیو و اتصال بازبینی، کش، ذخیره/بازخوانی و قفل‌ها تأیید شدند. cleanup شش دیتابیس موفق بود و بررسی مستقل SQL هیچ دیتابیس QA باقی‌مانده‌ای نشان نداد. تصاویر ادیتور و PDF برای مرز جدول بدون عنوان، عنوان تکرارشونده و صفحات اول/آخرِ سربرگ‌دار بازبینی شدند؛ در نمونه‌های منتخب بریدگی یا هم‌پوشانی دیده نشد.

رگرسیون پس از اصلاح: ۶۶ تست JavaScript و ۹ سناریوی مرورگر مستقلِ قبلی پاس شدند؛ آزمون‌های عادی شامل ۵۳۷ Domain و دو Architecture موفق و ۳۵ مورد skip بودند. آزمون SQLدار در اجرای عادی skip و با اسکریپت بالا جدا فعال می‌شود. build کل راه‌حل صفر خطا و هشدار داشت. دو اسکریپت قدیمیِ قالب/پاورقی نیز برای انتظار شناسهٔ چاپگر جاری v11 به‌روز شدند؛ زنجیرهٔ کامل آن دو اسکریپت در این اجرا تکرار نشده است.

قالب سادهٔ قدیمی با ریشهٔ `doc` از نظر سرور معتبر بود، اما اعتبارسنج نمای صفحه‌ای فقط ریشهٔ `header`/`footer` را می‌پذیرفت. نمای صفحه‌ای اکنون همان نمایش قدیمیِ معتبر را می‌پذیرد؛ ویژگی ناشناخته یا ویژگی مخصوص قالب به ریشهٔ `doc` تحمیل نمی‌شود و JSON ذخیره‌شده عوض نمی‌شود.

خلاصهٔ اعتبارسنجی پیش‌فرض MVC در فرم ورود و قالب، یک عنصر دارای inline style تولید می‌کرد که با CSP فعلی ناسازگار بود. خلاصهٔ مشترکِ خطاها جایگزین شد؛ پیام‌ها با Razor encode می‌شوند، عنصر پنهانِ دارای style نداریم و سیاست امنیتی ضعیف نشده است. در فرم ورود، مقدار رمز از ModelState پاک می‌شود ولی خطای اعتبارسنجی آن حفظ می‌شود.

## محدودیت نتیجه

این آزمون مهاجرت‌ها را فقط روی دیتابیس‌های تازهٔ خودش اجرا می‌کند؛ ارتقای دیتابیس موجود، پشتیبان‌گیری/بازیابی، تبدیل آرشیو قدیمی یا استقرار برنامهٔ اصلی انجام نمی‌شود. ماتریس کامل نقش‌های مترجم/بازبین، انقضای اشتراک، دو کاربر هم‌زمان، تمام مرورگرها و تمام مرزهای خطوط هنوز در این آزمون پوشش کامل ندارند. امضای واقعی و اتصال نوتر نیز خارج از محدوده‌اند.

پیش از ارتقای دیتابیس موجود، [راهنمای نسخه‌بندی محتوا](document-content-versioning.fa.md) را دنبال کنید. قابلیت و محدودیت چیدمان: [راهنمای صفحه‌بندی](editor-pagination.fa.md).
