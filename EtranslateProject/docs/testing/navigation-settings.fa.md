# راهنمای منو و صفحهٔ مستقل قالب‌ها — قدم اول

این راهنما شرح تاریخی قدم اول، یعنی جداسازی صفحات و ناوبری است. اکنون قدم دوم، شامل انتخاب/ویرایش قالب و لوگو هنگام ساخت اولیه نیز اضافه شده است؛ برای رفتار فعلی فرم‌ها، [راهنمای قدم دوم](template-editing.fa.md) را بخوانید. سربرگ کامل تصویری، تراز اجزا، پابرگ فقط صفحهٔ آخر و اتصال قالب بعد از ذخیره هنوز متعلق به قدم‌های بعدی‌اند.

## راه‌اندازی و تست دستی

اگر پروژه در Visual Studio در حال اجراست، ابتدا اجرای آن را متوقف کنید؛ سپس Build و دوباره اجرا کنید. بازآوری مرورگر به‌تنهایی صفحات کامپایل‌شدهٔ قدیمی را عوض نمی‌کند.

1. وارد حساب شوید و یک فضای کاری انتخاب کنید. منوی اصلی باید «پرونده‌ها، کارهای من، اعضای تیم، اشتراک، تنظیمات» را نشان دهد. لینک اعضای تیم فقط برای مالک/مدیر است.
2. صفحهٔ پرونده‌ها دیگر نباید فرم ساخت قالب یا بارگذاری لوگو داشته باشد. ایجاد پرونده و انتخاب فضای کاری مثل قبل باقی می‌مانند.
3. «تنظیمات» سپس «باز کردن مدیریت قالب‌ها» را بزنید؛ فهرست و فرم‌های قالب در صفحهٔ جدا هستند. فضای کاری جاری نباید تغییر کند.
4. یک قالب جدید بسازید. پس از ثبت باید به همان صفحهٔ قالب‌ها، در همان فضای کاری برگردید.
5. در نسخهٔ فعلی، لوگوی PNG/JPEG را هنگام ساخت اولیه یا ویرایش از همان فرم انتخاب کنید؛ نسخهٔ جدید ساخته می‌شود و بازگشت به صفحهٔ قالب‌هاست. مسیر قدیمی بارگذاری جداگانه نیز برای سازگاری باقی مانده است.
6. فضای کاری دیگری را در همان صفحه انتخاب کنید؛ فقط قالب‌های آن فضا دیده شوند. «پرونده‌ها»، «کارهای من» و «اشتراک» باید به فضای انتخاب‌شده بروند.
7. ویرایشگر پرونده را باز کنید؛ انتخاب و تثبیت قالب قبل از اولین ذخیره مثل قبل است. لینک مدیریت قالب در تب جدا باز می‌شود تا متن ذخیره‌نشده از دست نرود. قالب پس از اولین ذخیره هنوز قابل اتصال نیست.
8. با نقش Reviewer فهرست قالب‌ها خواندنی و فرم‌ها غیرفعال‌اند؛ درخواست مستقیم نوشتن هم رد می‌شود. تغییر نقش یا غیرفعال‌شدن عضویت همچنان سمت سرویس‌ها کنترل می‌شود.
9. پس از انقضای اشتراک، فهرست قالب‌ها باقی می‌ماند ولی تغییرات مسدودند؛ انتقال صفحه اشتراک را فعال یا تمدید نمی‌کند.
10. با عرض موبایل، منو باید چندخطی و قابل استفاده باشد؛ فرم‌ها زیر هم قرار بگیرند و صفحه اسکرول افقی نداشته باشد.

آدرس‌ها:

```text
/Workspace?tenantId=<id>
/Workspace?tenantId=<id>&assignedToMe=true
/Settings?tenantId=<id>
/Settings/Templates?tenantId=<id>
```

قالب‌ها دادهٔ همان فضای کاری‌اند، نه تنظیم سراسری حساب. آدرس فضای غیرعضو نباید اطلاعاتش را نمایش دهد. شمارهٔ نسخه، فایل‌ها و PDFهای قبلی با این تغییر عوض نمی‌شوند؛ Migration جدید لازم نیست.

## تست خودکار

با برنامهٔ متوقف، از پوشهٔ Solution:

```powershell
dotnet build ETranslate.slnx
dotnet test ETranslate.slnx
```

سپس AppHost و SQL Server محلی را اجرا کنید. با PowerShell 7 و مرورگر تست/PDF نصب‌شده:

```powershell
./tests/ETranslate.EndToEndTests/Verify-Navigation.ps1
```

اسکریپت فقط HTTP loopback را قبول می‌کند. تست‌های پایهٔ وب/تیم، ساخت قالب و بازگشت به تنظیمات، جداسازی فضاها، دسترسی ناظر، CSRF و یک تست واقعی مرورگر را اجرا می‌کند. حساب‌ها و پرونده‌های ساختگی نگه داشته می‌شوند؛ روی محیط واقعی اجرا نکنید. تصاویر بررسی دسکتاپ و موبایل در `tmp/navigation-qa` قرار می‌گیرند. تست مرورگر در اجرای عادی `dotnet test` عمداً Skip است و اسکریپت فقط با اطلاعات ساختگی همان اجرا فعالش می‌کند.

برای ساخت جداگانه هنگام قفل‌بودن فایل‌های خروجی توسط Visual Studio:

```powershell
dotnet test ETranslate.slnx --artifacts-path tmp/navigation-build
```

اگر Web جدید را جداگانه روی پورت 5068 اجرا کرده‌اید و APIهای محلی فعال‌اند:

```powershell
./tests/ETranslate.EndToEndTests/Verify-Navigation.ps1 -WebUrl http://localhost:5068 -TestArtifactsPath tmp/navigation-build
```

خروجی ساخت جدا، اجرای فعلی Visual Studio را به‌روزرسانی نمی‌کند. برای استفادهٔ معمول، همان توقف/Build/اجرای مجدد لازم است.

## هشدار جداگانهٔ وابستگی

در بررسی این مرحله، NuGet برای وابستگی موجود `System.Security.Cryptography.Pkcs` نسخهٔ 9.0.11 هشدار امنیتی داد. این هشدار مربوط به تغییر منو نیست و در این قدم بسته‌ای ارتقا داده نشده است. رسیدگی به نسخهٔ runtime و بسته‌های وابسته باید پیش از انتشار عمومی جداگانه انجام شود؛ جزئیات و منابع در ADR 0021 آمده‌اند.
