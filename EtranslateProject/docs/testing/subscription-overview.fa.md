# راهنمای تست صفحهٔ اشتراک

این قدم فقط نمایش امن وضعیت اشتراک است. پرداخت، خرید یا تمدید اشتراک، تعیین قیمت و محدودکردن امکانات بعد از انقضا هنوز پیاده‌سازی نشده‌اند.

## اجرای پروژه

در پوشهٔ راه‌حل، AppHost را اجرا کنید:

```powershell
dotnet run --project src/Orchestration/ETranslate.AppHost/ETranslate.AppHost.csproj
```

وارد سایت شوید و فضای کاری موردنظر را انتخاب کنید. در صفحهٔ فضای کاری روی «وضعیت اشتراک و دورهٔ آزمایشی» بزنید. برای دارالترجمه و مترجم مستقل این لینک وجود دارد.

## تست موردبه‌مورد

1. با حساب مالک، یک فضای کاری جدید بسازید. پس از پردازش رویداد ایجاد فضای کاری، اشتراک آزمایشی آن خودکار ایجاد می‌شود. مشاهدهٔ صفحه، اشتراک جدیدی ایجاد نمی‌کند.
2. صفحه باید «دورهٔ آزمایشی فعال»، نوع فضای کاری، دورهٔ آزمایشی ۳۰روزه، روز باقی‌مانده، زمان شروع، پایان و زمان بررسی وضعیت را نشان دهد. همهٔ زمان‌های نمایشی صریحاً به ساعت استانبول، `UTC+03:00` هستند.
3. دوره دقیقاً ۳۰ روز است، نه یک ماه تقویمی. کسر روز به بالا گرد می‌شود؛ برای مثال کمتر از یک روز باقیمانده «۱ روز» نمایش داده می‌شود. لحظهٔ دقیق پایان در همان صفحه دیده می‌شود و پس از آن روز باقی‌مانده صفر است.
4. «بررسی دوبارهٔ وضعیت» را بزنید یا صفحه را بازآوری کنید. زمان بررسی عوض می‌شود، اما تاریخ شروع و پایان آزمایشی نباید تمدید یا دوباره ایجاد شود.
5. با اعضای فعال Owner، Administrator، Translator و Reviewer وارد شوید. همگی وضعیت همان فضای کاری را می‌بینند. این اشتراک مشترک فضای کاری است، نه اشتراک شخصی هر عضو؛ هیچ‌کس از این صفحه نمی‌تواند آن را تغییر دهد.
6. عضویت یک مترجم را از مدیریت اعضا غیرفعال کنید. با حساب همان مترجم دوباره صفحه را باز کنید: دسترسی ندارد. فعال‌سازی مجدد دسترسی خواندن را برمی‌گرداند. تغییر نقش مترجم به Reviewer نیز دسترسی خواندن را حفظ می‌کند.
7. لینک صفحه را با حسابی که عضو آن فضای کاری نیست باز کنید: اطلاعات اشتراک نمایش داده نمی‌شود و پاسخ صفحه ۴۰۴ است. بدون ورود، به صفحهٔ ورود منتقل می‌شوید. شناسهٔ فضای کاری دیگر یا تغییر یک هدر نباید دسترسی ایجاد کند.
8. اگر رویداد ایجاد هنوز پردازش نشده باشد، «در انتظار ایجاد اشتراک» می‌بینید؛ نه آزمایشی ساختگی و نه منقضی‌شده. چند لحظه بعد دستی دوباره بررسی کنید. اگر این حالت پایدار ماند، سلامت Billing و پردازش رویدادها را بررسی کنید.
9. در محیط توسعه، Billing را موقتاً از داشبورد متوقف کنید و پس از پایان مهلت درخواست صفحه را بررسی کنید. باید خطای قابل‌بررسی نبودن وضعیت ببینید، نه وضعیت فعال یا منقضی‌شدهٔ ساختگی. فضای کاری فقط به‌دلیل توقف Billing نباید مسدود شود. سرویس را بعد از تست دوباره اجرا کنید. خرابی ارتباط Identity نیز نباید کنترل عضویت را دور بزند.
10. برای یک نمونهٔ آزمایشی منقضی‌شده، صفحه باید «منقضی‌شده»، صفر روز و پیام عدم اعمال محدودسازی را نشان دهد. فایل‌ها حذف نمی‌شوند و در این قدم ایجاد و ویرایش ترجمه همچنان مجاز است. هیچ دکمهٔ پرداخت یا تمدید فعالی وجود ندارد.

## API خواندن

مسیر Billing:

```text
GET /api/v1/tenants/{tenantId}/subscription
Authorization: Bearer <توکن حساب عضو فعال>
```

- `200`: اشتراک موجود؛ شامل وضعیت، زمان بررسی و تاریخ‌های دوره.
- `202`: فضای کاری مجاز است، اما اشتراک هنوز ایجاد نشده؛ وضعیت `Pending` بدون تاریخ ساختگی.
- `401`: ورود/توکن معتبر وجود ندارد.
- `403`: عضو فعال نیستید یا فضای کاری قابل‌دسترسی نیست.
- `503`: بررسی دسترسی از Identity ممکن نیست؛ اطلاعات اشتراک منتشر نمی‌شود.

مسیر قدیمی `/internal/v1/subscriptions/{tenantId}` هم اکنون دقیقاً همین کنترل دسترسی را دارد و دیگر بدون توکن خوانده نمی‌شود. درخواست POST یا PUT روی مسیر نمایش، اشتراک را تغییر نمی‌دهد. پاسخ‌های صفحه و API خصوصی و بدون کش هستند. توکن فقط سمت سرور سایت نگهداری می‌شود.

## تست خودکار محلی

با AppHost روشن، در PowerShell 7 و پوشهٔ راه‌حل:

```powershell
./tests/ETranslate.EndToEndTests/Verify-Subscriptions.ps1 -WebUrl http://localhost:5067
```

این تست، تست‌های فضای کاری و اعضا را هم اجرا می‌کند و داده‌های ساختگی ایجادشده را برای بررسی نگه می‌دارد. فقط روی محیط توسعه اجرا کنید. اگر پروفایل HTTPS دارید، آدرس Web را متناسب با داشبورد تغییر دهید.

تست اختیاری انقضا و ذخیرهٔ نمونه‌های ظاهری:

```powershell
./tests/ETranslate.EndToEndTests/Verify-Subscriptions.ps1 -WebUrl http://localhost:5067 -TestExpiredFixture -HtmlOutputDirectory ./tmp/subscriptions
```

گزینهٔ `TestExpiredFixture` فقط تاریخ‌های اشتراک فضای کاری مستقلِ ساخته‌شده در همان اجرای تست را با `sqlcmd` در SQL Server محلی `.\ESIMSSQLSERVER` و دیتابیس `ETranslateBilling` عقب می‌برد. دادهٔ واقعی یا فضای کاری قبلی هدف نیست؛ نمونهٔ منقضی‌شده باقی می‌ماند و این عملیات API محصول نیست. این گزینه را به محیط واقعی یا آدرس سرویس‌های غیرمحلی متصل نکنید. تست همچنین ایجاد ترجمه را پس از انقضا بررسی می‌کند، چون محدودسازی هنوز در محدودهٔ این قدم نیست.

فایل‌های HTML ذخیره‌شده نسخهٔ رندرشدهٔ صفحه‌اند؛ فرم، اسکریپت و لینک عملیاتی ندارند و فقط برای بررسی ظاهر هستند. نمونهٔ آزمایشی فعال و منقضی‌شده در پوشهٔ `tmp/subscriptions` ذخیره می‌شوند. خطاهای اتصال و پاسخ نامعتبر علاوه بر تست زندهٔ دسترسی، با تست‌های واحد پوشش داده شده‌اند.

برای تست‌های بدون زیرساخت:

```powershell
dotnet test ETranslate.slnx
```

هیچ Migration جدیدی برای این قدم لازم نیست. قواعد محدودسازی اشتراک، پرداخت و تمدید باید در قدم‌های جداگانه طراحی و آزمایش شوند.
