# راهنمای تست پیش‌نمایش PDF بدون امضا

این قابلیت برای دیدن صفحات ترجمه و بیانیه‌های **پیشنهادی** است؛ امضا، مهر دارالترجمه، رضایت امضاکننده، QR، تأیید نوتر یا سند معتبر حقوقی تولید نمی‌کند. ارائه‌دهنده‌ی واقعی امضا هنوز متصل نیست.

## شروع

از پوشه‌ی `EtranslateProject`:

```powershell
dotnet build ETranslate.slnx
dotnet run --project src/Orchestration/ETranslate.AppHost
```

پنل Web را از داشبورد باز کنید. موتور PDF باید قبلاً با `./scripts/Install-PdfBrowser.ps1` نصب شده باشد. Docker یا WSL لازم نیست؛ جدول مستقل پیش‌نمایش‌ها با migration در شروع Documents روی SQL Server ساخته می‌شود.

## موردبه‌مورد

1. با مالک یا مدیر، پرونده را باز کنید؛ ترجمه‌ی ذخیره‌شده را PDF کنید و همان نسخه را به تأیید داخلی برسانید.
2. «آماده‌سازی درخواست امضا در تب جدا» را باز کنید و برنامه را با انتخاب عضو فعال، روش و متن پیشنهادی ثبت کنید. برای مترجم مستقل یک مرحله و برای دارالترجمه دو مرحله لازم است.
3. در کارت برنامه‌ی فعال، «ساخت یا دریافت پیش‌نمایش PDF بدون امضا» را بزنید. متن ذخیره‌نشده‌ی ویرایشگر وارد این خروجی نمی‌شود.
4. لینک «دانلود پیش‌نمایش PDF — بدون امضا» را باز کنید. صفحات ترجمه‌ی مرجع با چیدمان قبلی در ابتدا هستند؛ پیوست، اطلاعات برنامه و سپس بیانیه‌ی هر مرحله را نمایش می‌دهد. سربرگ/مهر یا امضای جدیدی به صفحات ترجمه افزوده نمی‌شود.
5. در پیوست، هش با عنوان «Source PDF SHA-256» مربوط به فایل مرجع است، نه کل پیش‌نمایش. هش خود پیش‌نمایش در پنل و اطلاعات دانلود جداگانه ثبت می‌شود. شناسه‌ی امضاکننده فقط شناسه‌ی حساب است؛ هویت گواهی امضا یا صلاحیت رسمی او را اثبات نمی‌کند.
6. دوباره دکمه‌ی ساخت را بزنید؛ همان فایل بایگانی‌شده با همان شناسه و هش برمی‌گردد. PDF مرجع و فهرست PDFهای ترجمه تغییر نمی‌کنند.
7. متن فارسی، ترکی، چندخطی و متن شبیه HTML را امتحان کنید. بیانیه حداکثر ۴۰۰۰ نویسه دارد و بدون کوتاه‌سازی حفظ می‌شود. اگر متن روی چند صفحه بیفتد، ادامه‌ی آن در صفحات پیوست می‌آید. شماره‌ی صفحات ترجمه و پیوست عمداً جداست.
8. با حساب مترجم یا Reviewer، فایل‌های قبلی قابل دانلودند اما دکمه‌ی ساخت ندارید. عضو غیرفعال یا عضو فضای کاری دیگر به فایل دسترسی ندارد؛ لینک دانلود عمومی نیست.
9. برنامه را لغو کنید. فایل قبلی باقی می‌ماند ولی از آن برنامه پیش‌نمایش جدید ساخته نمی‌شود. برای تغییر بیانیه، برنامه‌ی تازه ثبت کنید؛ فایل قبلی بازنویسی نمی‌شود.
10. تأیید داخلی را بازگشایی کنید. برنامه‌ی قدیمی دیگر به تأیید جاری وصل نیست و دکمه‌ی ساخت آن حذف می‌شود. فایل قبلی فقط سابقه است: لغو یا بازگشایی بعدی داخل PDF ثابت منعکس نمی‌شود، پس وضعیت جاری را در پنل بررسی کنید.
11. PDF مجموعاً حداکثر ۵۰ صفحه و ۲۵ مگابایت دارد. خطای ساختار/محدودیت، هیچ متنی را حذف نمی‌کند؛ مشغول بودن موتور یا نبودن سرویس، پیام خطا می‌دهد. پس از پاسخ مبهم، ابتدا صفحه را تازه کنید و سابقه را ببینید، سپس تصمیم به تلاش مجدد بگیرید.

دکمه‌ی «ارسال برای امضای واقعی» همچنان غیرفعال است. این پیش‌نمایش، PDF نهایی آماده‌ی امضای واقعی نیست و نباید به‌عنوان سند امضاشده ارائه شود. برای اتصال آینده باید سند نهایی، هویت، اختیار و پذیرش واقعی بیانیه‌ها جداگانه مشخص و بررسی شوند.

صفحه ۲۰ برنامه و API فهرست پیش‌نمایش‌ها ۱۰۰ فایل اخیر را نمایش می‌دهد؛ سوابق قدیمی حذف نمی‌شوند. در این مرحله سهمیه‌ی اشتراک و پرداخت آنلاین اعمال نمی‌شود.

## تست خودکار

با AppHost روشن و PowerShell 7:

```powershell
./tests/ETranslate.EndToEndTests/Verify-SigningPreviews.ps1
# اگر پنل روی HTTP اجرا شده است:
./tests/ETranslate.EndToEndTests/Verify-SigningPreviews.ps1 -WebUrl http://localhost:5067
```

برای دریافت فایل‌های آزمایشی چندصفحه‌ای می‌توانید `-OutputDirectory ./tmp/pdfs/signing-preview-qa` را اضافه کنید. `-EmitBrowserFixture` مشخصات حساب آزمایشی را برای تست دستی چاپ می‌کند؛ خروجی آن را عمومی نکنید. این اسکریپت حساب‌ها، فضاها و اسناد ساختگی ایجاد می‌کند و نگه می‌دارد؛ روی production اجرا نکنید. تست‌های پایه‌ی پنل، تیم و برنامه‌ی امضا هم اجرا می‌شوند. اجرای `dotnet test` به‌تنهایی این تست HTTP را اجرا نمی‌کند.

بررسی این مرحله: ۲۶۷ آزمون واحد/معماری، ۲۷ آزمون مرورگرِ منطق کلاینت و ۴۰۶ بررسی زنده‌ی محلی موفق شدند. خروجی فارسی/ترکی، حالت مستقل/دارالترجمه و متن بلند با رندر صفحه‌به‌صفحه بررسی شدند؛ یک آزمون قدیمی EndToEnd که هنوز placeholder است، طبق قبل skipped می‌شود.
