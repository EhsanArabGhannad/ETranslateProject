# اتصال و تغییر قالب پس از ذخیره - قدم پنجم

## ارتقا و راه‌اندازی

این قدم Migration جدید `PinTemplatePerDraftRevision` دارد. همهٔ اجراهای قدیمیِ سرویس Documents را قبل از ارتقا متوقف کنید؛ اجرای هم‌زمان نویسندهٔ قدیمی با نسخهٔ جدید مجاز نیست. قبل از ارتقای محیط مهم، از پایگاه داده و فایل‌های آرشیوی نسخهٔ پشتیبان بگیرید. پروژه را Build و AppHost جدید را اجرا کنید؛ سرویس Documents در راه‌اندازی، Migration را مثل مراحل قبلی اعمال می‌کند.

Migration فقط یک ارتباط قالب به هر نسخهٔ ترجمه اضافه می‌کند. برای نسخه‌های قدیمی، قالب قبلیِ پرونده یا حالت بدون قالب را ثبت می‌کند؛ متن، PDF و مدارک مبدأ بازنویسی نمی‌شوند. این انتقال به این فرض معتبرِ نسخهٔ قبلی متکی است که قالب پس از اولین ذخیره قابل تغییر نبود. اگر داده‌های شما خارج از نرم‌افزار دست‌کاری شده‌اند، پیش از ارتقا بررسی جداگانه لازم است.

بعد از استفاده از تغییر قالب، بازگرداندن سادهٔ Migration می‌تواند تاریخچه را از بین ببرد؛ عملیات Down در صورت تفاوت قالب نسخه‌های تاریخی با قالب جاری عمداً متوقف می‌شود. برای بازگشت به نسخهٔ قدیمی باید از مسیر پشتیبان سازگار استفاده کنید، نه حذف دستی ستون.

## تست امکانات جدید

1. یک پرونده بدون قالب بسازید، متن ترجمه را بنویسید و ذخیره کنید.
2. در ویرایشگر، «اتصال یا تغییر قالب در تب جدا» را بزنید. صفحهٔ جدید، نسخهٔ ذخیره‌شده و قالب فعلی را نشان می‌دهد.
3. اگر متن ذخیره‌نشده در تب ویرایشگر دارید، ابتدا همان متن را ذخیره کنید، سپس صفحهٔ قالب پرونده را بازآوری کنید. صفحهٔ جدید متنِ در حال تایپ را نمی‌خواند و خودکار ذخیره نمی‌کند.
4. قالب مقصد را از فهرست انتخاب کنید و «ثبت قالب با ساخت نسخهٔ جدید» را بزنید. فقط نسخهٔ فعلیِ قالب‌های فعال در فهرست نمایش داده می‌شود.
5. شمارهٔ نسخهٔ ترجمه باید یک واحد افزایش یابد؛ متن و قالب‌بندیِ ذخیره‌شده عیناً باقی می‌مانند. متن اولیهٔ قالب مقصد جای ترجمه را نمی‌گیرد. سربرگ، پابرگ، واترمارک و تنظیمات صفحه از نسخهٔ انتخاب‌شده می‌آیند.
6. آخرین نسخهٔ ویرایشگر را در تب جدا باز کنید و PDF جدید بسازید. این نسخه باید قالب مقصد را داشته باشد.
7. نسخهٔ قبل از اتصال قالب را از تاریخچه باز کنید؛ باید بدون قالب باقی بماند. نسخهٔ دارای قالب قبلی هم باید همان قالب را نشان دهد، نه قالب جدید.
8. برای نسخهٔ تاریخی که تا حالا PDF نداشت، PDF بسازید؛ قالب همان نسخه باید استفاده شود. دانلود PDF آرشیوشدهٔ قبلی نیز باید همان فایل و شناسهٔ قبلی باشد.
9. قالب را دوباره به قالب دیگری یا نسخهٔ جدیدی از همان قالب تغییر دهید؛ باز هم نسخهٔ تازه ساخته می‌شود و تاریخچه حفظ می‌شود. انتخاب دقیقاً همان نسخهٔ قالب جاری، تغییر واقعی محسوب نمی‌شود و رد می‌شود.
10. از دو تب با شمارهٔ نسخهٔ یکسان ذخیره یا تغییر قالب را انجام دهید؛ فقط یکی باید موفق شود. در تب ویرایشگر قدیمی، متن ذخیره‌نشده حفظ می‌شود، ولی ذخیرهٔ کهنه با تعارض متوقف می‌شود. متن مهم را کپی و با آخرین نسخه تطبیق دهید؛ روی بازآوری کورکورانه حساب نکنید.
11. پرونده را برای بازبینی بفرستید یا تأیید کنید؛ تغییر قالب باید مسدود شود. پس‌گرفتن، برگشت برای اصلاح یا بازگشایی توسط مسئول مجاز، از مسیرهای قبلی انجام می‌شود. بعد از تغییر قالب، PDF و بازبینی تازه لازم است؛ تأیید یا برنامهٔ امضای قبلی به نسخهٔ جدید منتقل نمی‌شود.
12. با Reviewer، اشتراک منقضی، فضای کاری غیرمجاز یا قالب بایگانی‌شده امتحان کنید؛ مجوز جدیدی برای نوشتن ایجاد نشده است.

## محدودیت‌های عمدی

- تغییر فقط روی آخرین نسخهٔ ذخیره‌شده است، نه نسخهٔ تاریخی و نه متن داخل تب دیگر.
- اگر بدنهٔ ترجمه تصویر دارای شناسهٔ متعلق به قالب قبلی داشته باشد، انتقال به قالب دیگری که آن تصویر را ندارد رد می‌شود. تصویر، متن و ساختار غنی بی‌صدا حذف یا ساده نمی‌شوند. ارتقا به نسخهٔ دیگرِ همان قالب، با همان تصاویر معتبر ممکن است.
- لوگو/بنر سربرگ قالب مقصد جایگزین اجزای قالب قبلی در نسخهٔ جدید می‌شود، نه اینکه فایل‌های قدیمی پاک شوند. مدارک مبدأ پرونده مثل قبل مشترک و بدون تغییرند.
- قطع اتصال کامل قالب، جابه‌جایی/کپی خودکار فایل تصویر بین قالب‌ها و انتقال تأیید/امضای قبلی در این قدم ارائه نشده‌اند.
- وضعیت بازبینی نمایش‌داده‌شده کنار نسخهٔ تاریخی، وضعیت فعلی پرونده است؛ به‌معنای تأیید آن نسخهٔ تاریخی نیست.
- برنامه هنوز امضای واقعی یا تأیید نوتر را به این جریان اضافه نمی‌کند.

## آزمون خودکار

```powershell
dotnet build ETranslate.slnx
dotnet test ETranslate.slnx
```

با AppHost جدید، SQL Server محلی و مرورگر تست نصب‌شده:

```powershell
./tests/ETranslate.EndToEndTests/Verify-LateTemplates.ps1
./tests/ETranslate.EndToEndTests/Verify-PurchaseOrders.ps1
```

اسکریپت اول تست‌های پایهٔ وب/تیم/ناوبری، اتصال دیرهنگام، تغییر قالب، حفظ JSON و متن، PDF تاریخی، قفل بازبینی، مالکیت تصاویر، CSRF، جداسازی فضاها و مرورگر واقعی را اجرا می‌کند. آزمون SQL، رقابت تغییر قالب با ذخیره و بازبینی را با دو context مستقل بررسی می‌کند. آزمون انتقال داده‌های قدیمی فقط با پرچم SQL و زمان قطعِ مشخصِ قبل از ارتقا (`ETRANSLATE_TEMPLATE_MIGRATION_CUTOFF`) فعال است؛ این زمان را حدس نزنید و برای هر ارتقا ثبت کنید.

تست‌ها فقط loopback را قبول می‌کنند، داده‌های ساختگی می‌سازند و آن‌ها را نگه می‌دارند. آزمون SQL مانند سایر تست‌های فعلی پروژه به نمونهٔ توسعهٔ `ESIMSSQLSERVER` و پایگاه `ETranslateDocuments` متصل است؛ روی محیط واقعی اجرا نکنید. فایل‌های PDF نمونه و تصاویر مرورگر در `tmp/late-template-qa` قرار می‌گیرند و اعتبار حقوقی ندارند. نمایش PDF را جداگانه هم تصویری بررسی کنید.

قدم بعدی: تبدیل رابط اصلی به ترکی و LTR، مستقل از زبان/جهت متن ترجمه؛ سپس آزمون نهایی و تکمیل راهنماها.
