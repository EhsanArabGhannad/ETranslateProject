# راهنمای جدول در ترجمه

اکنون می‌توانید جدول ساده را در بدنهٔ ترجمه ایجاد، ویرایش و در PDF پیش‌نویس چاپ کنید. این قابلیت به درگاه پرداخت یا ارائه‌دهندهٔ امضا نیاز ندارد؛ PDF همچنان بدون امضا و بدون تأیید نوتر است.

## تست دستی

1. یک پروندهٔ قابل ویرایش باز کنید؛ در یک پاراگراف عادی کلیک و «جدول ۳×۳ با سطر عنوان» را بزنید. داخل فهرست، نقل‌قول یا جدول دیگری، ایجاد جدول غیرفعال است.
2. متن سلول‌ها را فارسی/ترکی وارد کنید. پررنگ، مورب، زیرخط و جهت پاراگراف مثل قبل کار می‌کنند. متن داخل جدول را هم می‌توانید انتخاب و قالب‌بندی کنید.
3. داخل سلول کلیک کنید؛ «سطر بعد» و «ستون بعد» را امتحان کنید. در انتهای جدول، Tab نیز می‌تواند سطر بعدی بسازد؛ سقف تعداد سطر همچنان رعایت می‌شود.
4. حذف سطر، ستون و کل جدول را امتحان کنید. «واگرد» و «ازنو» تغییرات جلسهٔ فعلی را برمی‌گردانند؛ گروه‌بندی چند تغییر پشت‌سرهم ممکن است یکجا باشد.
5. نسخهٔ جدید ذخیره و صفحه را بازآوری کنید؛ سلول‌ها و قالب‌بندی باید باقی بمانند. پیش‌نمایش سربرگ را باز کنید؛ جدول در بدنه دیده می‌شود.
6. PDF نسخهٔ ذخیره‌شده را بسازید. خطوط سلول، متن و جهت‌ها را بررسی کنید. سطر اول اگر تماماً عنوان باشد، در صفحات بعد تکرار می‌شود. سربرگ/پابرگ و نشانهٔ بدون امضا مثل قبل باقی می‌مانند.
7. نسخهٔ قدیمی را از تاریخچه باز کنید؛ جدول خواندنی است و دکمه‌های تغییر آن غیرفعال‌اند. ویرایش جدید نباید JSON یا PDF قبلی را تغییر دهد.
8. در دو تب ذخیرهٔ هم‌زمان را امتحان کنید؛ نسخهٔ قدیمی نباید نسخهٔ جدید را بازنویسی کند. محدودیت نقش، قفل بازبینی و اشتراک منقضی همان قوانین قبلی‌اند.

## محدودهٔ پشتیبانی

- حداکثر **۵۰ سطر و ۱۲ ستون در هر جدول**؛ ستون‌ها عرض مساوی دارند.
- سلول می‌تواند متن، عنوان، فهرست یا نقل‌قول داشته باشد؛ تصویر داخل سلول پشتیبانی نمی‌شود.
- ادغام سلول، جدول تو در تو، عرض دستی، رنگ/استایل دلخواه، فرمول و ورود کامل Word/Excel پشتیبانی نمی‌شوند.
- برای پاراگراف بعد از جدول می‌توانید از کلید پایین در انتهای جدول استفاده کنید. یک پاراگراف عادی، محل ایجاد جدول بعدی است.
- اگر ارتفاع یک سطر به‌همراه عنوان تکرارشونده از فضای چاپ یک صفحه بیشتر شود، PDF با خطای 422 ساخته نمی‌شود. متن را کوتاه یا در چند سطر مستقل تقسیم کنید؛ این بررسی مانع بریده‌شدن بی‌خبر متن می‌شود.

JSON دارای امکانات خارج از این محدوده، مانند قبل در حالت پیشرفته حفظ می‌شود؛ ویرایشگر غنی و پیش‌نمایش بدنه آن را تبدیل نمی‌کنند و PDF از آن ساخته نمی‌شود. انتقال از Word تضمین حفظ همهٔ قالب‌بندی‌ها نیست. پیش‌نمایش مرورگر صفحه‌بندی دقیق چاپ نیست؛ PDF دانلودشده را بررسی کنید.

## اجرا و تست خودکار

Migration جدید لازم نیست. از پوشهٔ Solution:

```powershell
dotnet build ETranslate.slnx
dotnet test ETranslate.slnx
dotnet run --project src/Orchestration/ETranslate.AppHost/ETranslate.AppHost.csproj
```

مرورگر PDF باید طبق راهنمای قبلی با `scripts/Install-PdfBrowser.ps1` نصب شده باشد. سپس با AppHost و SQL Server محلی روشن و PowerShell 7:

```powershell
./tests/ETranslate.EndToEndTests/Verify-EditorTables.ps1
```

اسکریپت فقط HTTP محلی می‌پذیرد، حساب/فضای کاری/پروندهٔ ساختگی تازه می‌سازد و علاوه بر تست پایهٔ وب، یک مرورگر Chromium مستقل را برای دکمه‌ها، ذخیره، بازآوری و حالت خواندنی اجرا می‌کند. نمونهٔ PDF چندصفحه‌ای در `output/pdf/translation-table-<runId>.pdf` ایجاد و داده‌های تست نگه داشته می‌شوند. روی محیط واقعی اجرا نکنید. تست مرورگر در `dotnet test` عادی عمداً Skip است؛ اسکریپت آن را با اطلاعات ساختگی همان اجرا فعال می‌کند.

برای تغییر کد مرورگر، در `src/Web/ETranslate.Web` با Node.js 22.13 یا جدیدتر:

```powershell
npm ci
npm test
npm run build
```

فایل‌های تولیدشدهٔ مرورگر ثبت شده‌اند؛ اجرای معمول .NET نیازی به Node.js ندارد. سرویس‌ها و مرورگر را پس از تغییر دوباره اجرا/بازآوری کنید. نسخهٔ موتور PDF به `v8-tables` تغییر کرده است؛ صدور مجدد نسخهٔ قدیمی ممکن است PDF جدیدِ مستقل بسازد، اما PDFهای آرشیوشده و نسخهٔ تأییدشده را بازنویسی نمی‌کند.
