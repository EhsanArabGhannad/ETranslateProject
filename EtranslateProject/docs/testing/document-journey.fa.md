# تست مسیر پرونده تا آماده‌سازی امضا

تاریخ: ۲۰۲۶-۱۱-۰۴

## چه چیزی بررسی شد؟

دو مسیر با شش سرویس واقعی، SQL Server و مرورگر مستقل آزمایش می‌شوند:

| مسیر | افراد و سیاست | تنظیم دریافت‌کننده/نوتر |
|---|---|---|
| دارالترجمه | مترجم و مدیر جدا؛ پیشنهاد دو مرحلهٔ مترجم و دفتر | بدون نیاز به نوتر؛ پروفایل پذیرش مشخص نشده |
| مترجم مستقل | مالک همان مترجم؛ پیشنهاد یک مرحله | نوتر لازم/روال فیزیکی؛ پروفایل سایر |

تنظیم نوتر در این آزمون فقط اطلاعات پرونده است؛ تأیید نوتر یا ارسال به آن انجام نمی‌شود. هر دو حساب اشتراک آزمایشی فعال دارند.

ترتیب مسیر:

1. ثبت حساب، ایجاد فضای کاری، فعال‌شدن trial؛ در دارالترجمه دعوت و پذیرش مترجم.
2. ایجاد پرونده و سند، ساخت و تثبیت قالب با سربرگ/پاورقی و بارگذاری فایل مبدا.
3. ورود مترجم به ادیتور، نوشتن متن فارسی/ترکی، ذخیره و بازخوانی نسخهٔ دوم.
4. تولید PDF همان نسخه و بررسی هش؛ آماده‌سازی امضا پیش از تأیید داخلی باید رد شود.
5. ارسال برای بازبینی؛ مترجم دفتر حق تأیید مدیریتی ندارد. مدیر تأیید می‌کند و ادیتور پس از بارگیری مجدد قفل می‌ماند.
6. ثبت پیشنهاد امضاکننده، روش و بیانیه از فرم سایت؛ متن شبیه script باید به‌صورت امن نمایش داده شود. مترجم مستقل فیلد مرحلهٔ دفتر ندارد.
7. تولید پیش‌نمایش بدون امضا، دریافت از API و لینک خصوصی سایت و تطابق SHA-256. PDF پیش‌نویس یک صفحه دارد. پیش‌نمایش شامل همان صفحه، یک صفحهٔ معرفی و صفحهٔ جدا برای هر مرحله است: چهار صفحه برای دفتر و سه صفحه برای مترجم مستقل. تولید مجدد همان فایل آرشیوشده را می‌دهد.
8. رد دسترسی با شناسهٔ فضای کاری دیگر و رد درخواست ارسال واقعی امضا با پاسخ ۵۰۱.
9. بازگشایی تأیید، قدیمی‌شدن طرح قبلی، رد تولید جدید از طرح قدیمی و لغو نسخه‌دار طرح. لغو تکراریِ نسخهٔ قبلی باید رد شود.
10. حفظ JSON و PDF قبلی، ثبت صحیح نویسنده و فایل مبدا در سابقه و تطبیق هر شش فایل نگهداری‌شده با دیتابیس.

این آزمون ترکیبی است: ایجادها، آپلود و تصمیم بازبینی از API واقعی انجام می‌شوند؛ ورود، ویرایش/ذخیره، فرم آماده‌سازی و تولید/دریافت خصوصی پیش‌نمایش از مسیر Web آزمایش می‌شوند. بنابراین ادعای کلیک‌شدن همهٔ فرم‌های محصول نیست.

## اجرا

اجرای نهایی `ea08883e048e4630a42428fa4127ec50` موفق بود: هر دو مسیر در حدود ۴۹ ثانیه گذشتند. [گزارش سناریوها](../../tmp/pdfs/document-journey/ea08883e048e4630a42428fa4127ec50/journey-report.json) و [گزارش پاک‌سازی](../../tmp/pdfs/document-journey/ea08883e048e4630a42428fa4127ec50/cleanup.json) باقی‌اند. چهار PDF تولیدشده در مجموع ۹ صفحه دارند؛ شمار صفحات و بایت/هش دریافت API و BFF بررسی شد. این قدم مقایسهٔ بصری تمام صفحات PDF نیست. تصویر صفحهٔ آماده‌سازی دفتر نیز بازبینی شد.

ساخت نهایی بدون هشدار و خطا بود. اجرای معمول solution شامل ۷۶۵ تست Domain و دو تست معماری موفق بود؛ ۸۰ تست اختیاری Domain و یک placeholder قدیمی E2E در اجرای معمول غیرفعال‌اند. بررسی SQL پس از پایان، صفر دیتابیس QA باقی‌مانده نشان داد. فهرست‌های خطای جاوااسکریپت، CSP و درخواست بیرونی مرورگر در اجرای پذیرش خالی بودند.

از ریشهٔ solution پس از restore وابستگی‌ها و نصب مرورگر PDF موجود پروژه:

```powershell
pwsh -NoProfile -File ./tests/ETranslate.EndToEndTests/Verify-DocumentJourney.ps1 -SqlServer '.\ESIMSSQLSERVER'
```

اسکریپت فقط به SQL محلی متصل می‌شود، شش دیتابیس تازه می‌سازد و شش برنامهٔ واقعی را روی پورت‌های تازه اجرا می‌کند. دادهٔ کاربر و تنظیمات برنامه استفاده/اصلاح نمی‌شوند. مرورگر پروفایل مستقل دارد؛ Word یا مرورگر باز کاربر کنترل نمی‌شود. دانلود یا نصب خودکار مرورگر انجام نمی‌شود.

گزارش `journey-report.json`، چهار PDF ساختگیِ تولیدشده توسط چاپگر واقعی و تصاویر دو صفحهٔ آماده‌سازی زیر `tmp/pdfs/document-journey/<run>` قرار دارند. صفر بودن فهرست‌های `errors`، `external` و `csp`، موفقیت هر دو case و `cleanupSucceeded=true` با شش دیتابیس تازه باید تأیید شود. کپی‌های PDF گزارش از شش فایل اصلی ذخیره‌سازِ آزمون جدا هستند؛ ابزار inventory فقط فایل‌های پوشهٔ ذخیره‌ساز را تطبیق می‌دهد.

ساخت این قدم کد محصول را تغییر نمی‌دهد؛ پذیرش و راه‌انداز تست اضافه شده‌اند. در توسعهٔ fixture، فرض اشتباه دربارهٔ وجود userId در پاسخ login و layout خالی اصلاح شدند؛ هویت از endpoint دسترسی و layout از پیش‌فرض نسخه‌دار محصول خوانده می‌شود.

## حدود نتیجه

پیش‌نمایش و طرح، امضای دیجیتال، رضایت امضاکننده، تأیید حقوقی، نوتر یا مدرک نهایی امضاشده نیستند. سرویس خارجی امضا در این آزمون فراخوانی نمی‌شود. ثبت دوبارهٔ طرح پس از نسخهٔ تأییدشدهٔ تازه، مرورگر/دستگاه‌های دیگر، همهٔ نقش‌ها و اشتراک‌ها و انتشار عملیاتی به پذیرش جدا نیاز دارند.

این قدم مکمل [تست نقش‌ها](editor-access.fa.md)، [هم‌زمانی](editor-concurrency.fa.md)، [آپلود](editor-upload-recovery.fa.md) و [بازیابی](storage-restore.fa.md) است؛ مرحلهٔ آزمون جامع هنوز صرفاً با این دو سناریو کامل اعلام نمی‌شود. [ADR 0056](../adr/0056-isolated-document-to-signing-preparation-journeys.md) محدودهٔ فنی را ثبت می‌کند.
